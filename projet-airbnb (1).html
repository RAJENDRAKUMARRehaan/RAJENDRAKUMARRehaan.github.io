Contexte

Ce projet analyse les données publiques des logements Airbnb à Paris pour comprendre les tendances du marché locatif court terme. L'objectif était de mettre en pratique la collecte, le nettoyage et l'analyse de données réelles avec Python et SQL.

Ce que j'ai fait

  • Collecte des données depuis le dataset public Inside Airbnb
  • Nettoyage complet avec Pandas : valeurs manquantes, outliers, conversion des types
  • Filtrage sur les prix sous le 99e percentile (2 000 euros) et séjours courts (moins de 30 nuits)
  • Import dans une base MySQL locale et interrogation via des requêtes SQL
  • Analyse exploratoire et visualisation avec Matplotlib et Seaborn

Visualisations

Analyse

La première chose qui saute aux yeux, c'est l'écart entre la médiane et la moyenne des prix : 161 euros contre 236 euros. Cet écart montre que le marché est tiré vers le haut par une minorité de logements très chers. La médiane est bien plus représentative du prix réel auquel la majorité des voyageurs font face.

Sans surprise, le quartier de l'Élysée arrive en tête des quartiers les plus chers, suivi par Louvre et Luxembourg. Ces quartiers concentrent les logements entiers qui représentent plus de 80% de l'offre dans le top 5, ce qui explique en partie les prix élevés.

Un résultat inattendu : les logements avec une forte disponibilité annuelle (271 à 365 jours) affichent les prix moyens les plus élevés. On pourrait penser que les hôtes professionnels baisseraient leurs prix pour maximiser le taux d'occupation, mais les données montrent l'inverse. Ce sont souvent des logements de qualité supérieure qui peuvent rester chers tout en étant disponibles.

Enfin, le nombre d'avis n'a quasiment aucun impact sur le prix moyen. Que le logement ait 0 ou 50 avis, le prix reste autour de 200 à 230 euros. La réputation ne semble pas être un levier de tarification significatif sur ce marché.

Ce projet m'a appris à travailler sur des données réelles et imparfaites avec des valeurs aberrantes, des colonnes mal renseignées et des distributions très asymétriques. C'est bien plus formateur que des données propres de tutoriels.

Nettoyage et préparation des données
df = pd.read_csv("data/listings.csv", dtype=str, engine="python") # conversion en numérique cols_numeric = ["price", "minimum_nights", "number_of_reviews", "reviews_per_month", "availability_365"] for col in cols_numeric: df[col] = pd.to_numeric(df[col], errors="coerce") # filtrage : prix sous le 99e percentile et séjours courts df_clean = df[df["price"] <= 2000] df_analysis = df_clean[df_clean["minimum_nights"] <= 30] # export et import MySQL df_analysis.to_csv("data/listings_clean.csv", index=False) df_analysis.to_sql("listings", con=engine, if_exists="replace", index=False)

Requêtes SQL

Prix moyen par type de logement
SELECT room_type, ROUND(AVG(price), 2) AS prix_moyen FROM listings GROUP BY room_type ORDER BY AVG(price) DESC;
Top 10 quartiers les plus chers
SELECT neighbourhood, ROUND(AVG(price), 2) AS prix_moyen, COUNT(*) AS nombre_logements FROM listings GROUP BY neighbourhood ORDER BY AVG(price) DESC LIMIT 10;
Analyse par catégorie de prix
SELECT CASE WHEN price < 100 THEN 'Bas (< 100 euros)' WHEN price < 200 THEN 'Moyen (100-200 euros)' WHEN price < 400 THEN 'Élevé (200-400 euros)' ELSE 'Premium (> 400 euros)' END AS categorie_prix, ROUND(AVG(availability_365), 2) AS disponibilite_moyenne, COUNT(*) AS nombre_logements FROM listings GROUP BY categorie_prix ORDER BY MIN(price);
Prix par quartier et type de logement (top 5)
SELECT neighbourhood, room_type, ROUND(AVG(price), 2) AS prix_moyen FROM listings WHERE neighbourhood IN ('Élysée','Louvre','Luxembourg','Palais-Bourbon','Passy') GROUP BY neighbourhood, room_type ORDER BY AVG(price) DESC;
